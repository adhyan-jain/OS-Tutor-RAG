# Preregistration V2 — Reference anchoring of LLM judges on nondeterministic OS execution traces

**Frozen:** 2026-10-02, before the v2 leakage audit and before any language model output was produced.
**Freeze mechanism (user's choice):** this file is hashed with SHA-256; every results file stores the hash. Any edit after the freeze changes the hash and must be recorded as a deviation in §9.
**Supersedes:** `docs/PREREGISTRATION.md` (AGY). That document was written alongside the results it "predicted". Its leakage threshold (0.58) equalled the observed attacker accuracy (0.58), and none of its tests were implemented.

## 1. Research question

When an LLM judges whether an execution trace of an OS scheduling or synchronisation problem is valid, and the problem admits several valid traces, does supplying one valid reference trace make the judge reject *other* valid traces, beyond generic effects of adding context?

Secondary questions:
- How large is the gap between exact-match-to-reference scoring and validator scoring of model-generated traces?
- Does that gap change model rankings?
- Does any effect scale with the number of valid executions?
- Does it survive OOD splits?

## 2. Benchmark (fixed before the freeze)

- **Benchmark:** `research/benchmark/benchmark_v2.json`, generated by `research/benchmark/generator.py`, seed 20261002. The file has 630 instances: id 150, lexical_ood 80, long_trace 80, high_branching 80, rr_primitive 80, struct_mutex 80, struct_semaphore 80.
- **Traces per instance:** R1 is canonical valid, R2 is sampled valid (substantively different from R1), R3 is a third valid trace, I and I2 are invalid. Invalid traces keep the same segment or event multiset, the same length and the same per-entity totals as the valid traces, and are distance-matched to R2.
- **Labels:** every label is confirmed by two independent oracles (`validators.py` and the enumerators' membership tests).

## 3. Leakage audit (gate; thresholds frozen here)

- **Primary target:** R2 (valid alternative) vs I (invalid). This is binary, so chance = 0.50.
- **Secondary target:** R1 / R2 / I, three-way, so chance = 0.333. R1 is canonical *by rule*, so above-chance R1 identification is reported but is not a failure.
- **Attackers:** length/token counts; position of first divergence from R1; character 2–5-gram TF-IDF + logistic regression; word uni/bigram bag-of-words + logistic regression; reference-similarity features to R1 (edit distance, difflib ratio, bigram Jaccard) + gradient boosting; adjacent-pair "local plausibility" tokens + logistic regression; bge-large-en-v1.5 embeddings (trace, and trace − R1) + logistic regression.
- **Protocol:** grouped 5-fold CV (grouped by instance) × 5 seeds. The 95% CI comes from an instance-level bootstrap with 2,000 resamples. It is run pooled and separately per domain (scheduling, concurrency).
- **Failure rule:** an attacker fails the benchmark if the **lower bound** of its 95% CI is above chance + 0.05 on the primary target, pooled or in either domain. On failure the benchmark is redesigned and the audit re-run. The threshold is never changed.
- **Non-gating diagnostic:** a TF-IDF model given *problem + trace* text. This measures how learnable the task is, not leakage.

## 5. Experiments

### E1 — generation
All 630 instances, one call each. The model outputs a trace, which is parsed and normalised. Scores:
- Acc_ref = [T = R1]
- Acc_multi = [T ∈ {R1, R2, R3}]
- Acc_sem = V(P, T)
- RSG = Acc_sem − Acc_ref

A parse failure counts as wrong under every scorer. Also reported: canonical rate = P(T = R1 | V(P, T)).

### E2 — judging
The answer is one word, VALID or INVALID. Reference conditions:

| Split | Candidate | References |
|---|---|---|
| id | R2 | none, R1, R3, R2 (self), R1 reworded (other format), I2 (invalid ref), irrelevant (another problem's R1) |
| id | I | none, R1, R3 |
| id | R1 | none, R1 (self), R3 |
| other six splits | R2 | none, R1, R3, R2 (self) |
| other six splits | I | none, R1 |

- **Mitigation arm (id only):** candidate ∈ {R2, I} with ref R1, plus the sentence "The reference is one valid execution; other valid executions may exist."
- **Noise floor:** a seeded 10% sample of E2 cells, re-run once with identical settings. The noise flip rate is the share of cells whose verdict changes.

### E3 — ranking
- **Primary:** rank models by Acc_ref and by Acc_sem on E1. Report Kendall τ, and P(τ < 1) under an instance bootstrap with 2,000 resamples.
- **Secondary:** score every model's E1 outputs with one LLM judge given ref R1, and compare the resulting ranking with the Acc_sem ranking. The judge is chosen by a fixed rule: the model with the highest no-reference balanced accuracy on id in E2.

### E4 — scaling
- Logistic regression of accept(R2 | ref R1) and of RSG_i on log2|V|, trace_len, n_entities, dist_R1_R2 and domain, with an instance-cluster bootstrap for the CIs.
- Spearman correlation between log2|V| quartile and the metric.
- "Systematic" means the bootstrap CI of the log2|V| coefficient excludes 0.

### E5 — OOD
E1 and E2 metrics reported per split.

## 6. Hypotheses and primary tests

For each model m, among cells where the candidate is the valid alternative R2:

- **H2 (anchoring; primary).** AI_m = accept(R2 | ref = R2) − accept(R2 | ref = R1) > 0. Tested with an exact one-sided McNemar on paired instances (id ∪ all splits; pairs with any parse failure are dropped).
- **H2b (beyond generic context).** accept(R2 | ref = R1) < accept(R2 | ref = irrelevant) and < accept(R2 | none), on id. If accept(R2 | ref = R1) ≈ accept(R2 | ref = irrelevant), the effect is reported as a generic context effect, not reference anchoring.
- **H3 (which valid reference matters).** The flip rate between ref = R1 and ref = R3 for the same (P, R2) exceeds the noise-floor flip rate. Tested with a two-proportion exact test.
- **H1 (descriptive).** E1 RSG ≥ 0 holds *by construction*, because R1 ∈ V(P). Only its magnitude, with a CI, is reported. It is not presented as a finding.
- **H4 (ranking).** P(τ_ref,sem < 1) ≥ 0.95 under the bootstrap ⇒ "rankings change". If the point estimate τ = 1 ⇒ "no ranking change".
- **H5 (scaling).** As defined in E4.

**Multiplicity:** Holm correction over the family {H2_m, H3_m : all included models}, α = 0.05. Everything else is reported with 95% CIs and is not treated as confirmatory.

## 7. Decision rules (frozen)

- **No anchoring claim** if AI is not significant after Holm for a majority of included models, or if the H2b control fails.
- **No reference-choice claim** if H3 fails for a majority of models.
- **No ranking-impact claim** if H4 fails.
- **"Effect disappears OOD"** if AI's 95% CI includes 0 on a split while id's CI excludes 0. Any such split is listed as a central limitation.
- **Overall outcome:** if both H2 and H3 fail, the paper verdict is **KILL**. If H2 holds but H2b fails, the verdict is **MODIFY**, recast as a "context-sensitivity" note.

## 9. Deviations

Each deviation is appended here with its date and reason, which changes the hash.

- **D1 (2026-10-02, before any leakage-audit result was seen and before any model call).** The test suite found that in the rr_primitive split, invalid traces were length-matched to their base trace but not to R2. That matters because RR traces can differ in segment count. The generator now matches I to R2 on length first, then on edit distance to R1. The benchmark was regenerated with the same seed, and the leakage audit then in progress on the old file was stopped without its output being read. The validator's reason label for a cut-short burst was also renamed to `preempted_partial_burst`, and the event parser now accepts table rows. Neither change affects any label.
- **D2 (2026-10-02, after the leakage audit FAILED, before any model call).**
  - **What failed.** On the primary target (R2 vs I), three attackers had CI lower bounds above 0.55: divergence position (0.591 [0.570, 0.613]), reference similarity (0.608 [0.586, 0.631]) and local plausibility (0.602 [0.579, 0.625]). The mechanism: valid traces share their opening with R1 more often, and invalid concurrency traces contain adjacent pairs that never occur in valid traces.
  - **Redesign, as §3 requires; the threshold was not changed.**
    - (i) Every adjacent pair of I must occur in some valid trace.
    - (ii) I is matched exactly to R2 on length, first divergence from R1, last divergence from R1, and edit distance to R1.
    - (iii) Adversarial filtering: bag-of-words, adjacent-pair and reference-similarity attackers are trained on an auxiliary benchmark (seed 99173, disjoint problems). Among the matched candidates, I is the one whose attacker scores are closest to R2's.
  - **Result after redesign.** Pooled and scheduling pass. Concurrency still fails the adjacent-pair attacker (0.628 [0.588, 0.666]). Iteration stopped at that point, because further filtering against the audit's own attackers would overfit the audit.
  - **Consequence (fixed now, before any model output).** Concurrency splits stay in H2/H3: those compare the same valid R2 under different references, and I does not enter them. Every valid-vs-invalid discrimination result on concurrency is reported as **audit-failed** and is not used for any claim.
  - **Selection effect.** The redesign rejects many candidate problems, so the benchmark over-represents problems that admit a locally plausible invalid trace.
- **D3 (2026-10-02, after the full post-D2 audit, before any model call).** The bge-embedding attacker also fails: concurrency 0.710 [0.674, 0.744] and pooled 0.576 [0.559, 0.594]. Scheduling passes every attacker, bge included at 0.546 [0.526, 0.565], so the pooled failure is driven by concurrency. No further redesign was done. The D2 consequence is extended: **every valid-vs-invalid discrimination claim is restricted to the scheduling splits**, and pooled discrimination figures are descriptive only. H2/H3 do not involve I and are unaffected.
